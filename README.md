# 《漢末群雄志》V0.2.0

繁體中文、原創 SVG 山河的單機回合制策略遊戲。214 年「群雄對峙」架空劇本，選擇曹操、劉備、孫權，經營十二城、指揮三十名武將，直到統一天下或領土盡失。

## 執行

需要 Node.js 24（建議）與 npm 11。無後端、帳號、API 或額外服務。

```sh
npm ci
npm run dev
```

Vite 設定子路徑 `/hanmo-strategy/`，請開啟終端顯示的完整路徑。

```sh
npm run typecheck
npm run test
npm run build
npm run preview
```

`npm run test` 使用 Vitest 執行既有測試；`build` 先檢查 strict TypeScript，再輸出至 `dist/`。本機驗證結果及設計見 [GAME_DESIGN.md](GAME_DESIGN.md) 與 [ARCHITECTURE.md](ARCHITECTURE.md)。

## 玩法

1. 選擇諸侯；已有存檔時可繼續，或確認刪除後開新局。
2. 點擊地圖城池查看資源、經濟、五項城池能力和武將。地圖上下左右可捲動，右上角可縮放，點百分比可重設縮放與捲動位置；鍵盤 Tab、Enter 也能選城。
3. 己城可執行開墾、商業、徵兵、訓練、巡察及修築。巡察（金 200）提升治安，修築（金 320）提高真正的守城戰力；上限均為 100。每城每月最多三令，每將每月一動。成功後自動選下一位可用武將，面板顯示數值變化；手動選擇仍待命的武將會保留。
4. 「調動」可讓一名武將攜兵與糧移往相鄰友城。保留五百守軍；武將抵達後本月仍算已行動。
5. 「出征」選相鄰敵城、武將與兵數，在軍議選擇「親自指揮」或「委任作戰」。取消不扣資源，選定模式開始後才預留兵力、消耗軍糧及指令。委任沿用原自動公式，親征進入 8×6 戰術棋盤。
6. 結束本月會讓另外兩國行動，再結算全圖金糧、軍隊消耗、缺糧逃兵、年月與行動重置。軍情摘要列出實際事件。
7. 占領後指揮官和生還部隊進駐，新城當月不能再下令。守將撤退至其餘友城，亡國後成為無所屬。
8. 統一全部十二城獲勝；失去全部領土落敗。請在武將總覽查看全部三十名武將，包含無所屬者。

建議：用高政治武將開墾商業，高魅力武將徵兵，高統率武將訓練出征。把內地將領兵糧逐城調往前線，訓練成熟後集中優勢兵力出征。留意軍糧月支出，切勿只徵兵而不開墾。

## 存檔

V0.2.0 使用 schema version 2 及 `hanmo-strategy-save-v2`。每次戰略指令、戰術移動／攻擊／階段、戰果結算都自動儲存。關閉 Chrome 後重開，按「繼續遊戲」可回到同一場戰鬥、回合、兵力、地形、城門、火計額度與種子。

首次更新會在沒有 V2 的情況下驗證並讀取原有 `hanmo-strategy-save-v1`，只升級 schema，完整保留 V0.1.0／V0.1.1 世界狀態；進入遊戲後另存 V2，**原 V1 保留為備份，不會清除進度或要求重開**。

若 V2 損毀會停止載入並明確提示，不會靜默讀取舊 V1。首頁可「匯出現有存檔備份」，或確認後「復原 V1 備份」；後者會保存損毀 V2 至 `hanmo-strategy-save-v2-recovery-backup`（不覆蓋先前復原備份）。復原會回到 V1 當時的進度，務必先匯出。原有手動確認的新遊戲流程保留，V1 備份仍保留。進度限相同裝置／瀏覽器／網站來源，不跨裝置；禁止 LocalStorage 或空間不足會顯示存檔失敗。

## 親自指揮

- 每方依真實兵數分成最多三隊步兵、騎兵與弓兵，最多各一隊；一名主將可指揮多隊。少於三兵時減少隊數。
- 點己軍，再點綠格移動；移動後選「攻擊」並點紅框敵軍。步兵移動 2、騎兵平原 3（森林與山丘需多花移動力）、弓兵移動 2，射程為 2 格，高地可射至 3 格，不能貼身射擊。
- 每隊每階段移動一次、攻擊或火計一次。「待機」結束本隊並提供防禦加成，可提早按「結束階段」交給守軍。
- 智力至少 75 的主將可發動三格內火計，每軍每戰最多兩次；森林更容易成功，失敗仍消耗額度及攻擊行動。
- 近戰隊鄰接城門可「破城」，城門未破前攻方不能進入城區。勝利方式是全滅守軍，或破門後在內城（最右側中間道路）無鄰敵駐守兩個攻方結束階段。
- 守軍會移動、射擊與保衛城區。第 16 回合守軍結束階段仍未攻破時守軍勝；可確認「撤退」，生還部隊返回原城，已用軍糧與指令不退。
- 戰鬥中不能結束月份或另起戰鬥。完成後按「結算戰果 · 返回戰略地圖」，戰果只套一次；占領時主將和生還攻軍入駐，未被殲滅的守軍撤到其他友城，無處可退則潰散。
- 手機直向可直接玩。棋盤維持至少 44px 格子，在框內捲動／縮放；可勾「略過效果」。原創軍旗、地形及柔和動態，不需下載大型圖像。

## 發布 GitHub Pages

已提供 `.github/workflows/deploy.yml`，在 `main` push 或手動執行時，以官方 Actions 安裝、型別檢查、測試、建置、上傳 Pages artifact 及部署。

1. 將這些變更提交並推送到 `damx2002/hanmo-strategy` 的 `main`。
2. GitHub 儲存庫 → **Settings → Pages → Build and deployment → Source** 選擇 **GitHub Actions**。
3. 開啟 **Actions**，確認「部署 GitHub Pages」成功。若設定前執行失敗，可按 **Re-run all jobs**。
4. 發布網址為 `https://damx2002.github.io/hanmo-strategy/`。

部署結果應以對應提交的 Actions run 為準。若 repository 有環境保護規則，需依 GitHub 介面批准部署。其他靜態平台也可發布 `dist/`，但必須配合 base 路徑。

## 範圍與授權素材

原創城池資料、能力數值、抽象文字徽章、CSS 及 SVG。無引用 KOEI 圖像、音樂、人物肖像、標誌或程式碼。包含戰術棋盤及簡化火計；不含外交、單挑、戰術手動防守、多人或音樂。歷史地名與相對座標僅供戰略示意，不是史實交通或國界考據。
